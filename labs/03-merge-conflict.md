# Lab 03 - Merge conflict

## Checklist

- [ ] Maak twee branches die dezelfde regel in `submissions/conflict-demo.md` aanpassen.
- [ ] Merge één branch naar `main` via een PR.
- [ ] Werk je andere branch bij en laat het conflict bewust zien.
- [ ] Los het conflict lokaal op in VS Code.
- [ ] Controleer de oplossing met `git diff --check`.
- [ ] Commit de oplossing en licht je keuze toe in de PR.

## Reflectie

Waarom is een merge conflict geen fout op zich, maar een signaal dat Git jouw inhoudelijke beslissing nodig heeft?
