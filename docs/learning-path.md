# Leerpad

## Werkwijze

Per lab werk je in deze volgorde:

1. Lees het relevante doel in [study/exam-objectives.md](../study/exam-objectives.md).
2. Doe het lab in een aparte branch.
3. Leg in je pull request uit wat je deed en wat je geleerd hebt.
4. Link de PR of release terug in de voortgangstabel.
5. Noteer onzekerheden in [study/weak-topics.md](../study/weak-topics.md).

Gebruik [study/progress-log.md](../study/progress-log.md) als leerjournaal. Een korte reflectie na elk lab is nuttiger dan urenlang alleen video's kijken.

## GitHub in de browser

Gebruik GitHub.com voor repository settings, issues, pull requests, reviews, Projects, Discussions, releases, notifications en security settings. VS Code gebruik je voor bestanden, Git-commando's en conflictresolutie.

## Wanneer ben je klaar om het examen te boeken?

Boek pas nadat alle doelen zijn afgevinkt, elk lab een zichtbaar bewijs heeft, je de officiële GitHub Learn-stof hebt doorlopen en een externe practice assessment je zwakke onderwerpen blootlegt. Herhaal daarna alleen de onderdelen waar je nog fouten maakt.
