# Repository-instellingen - checklist voor GitHub.com

Deze instellingen kun je pas doorlopen nadat de repository naar GitHub is gepubliceerd. Zet niets aan zonder eerst te begrijpen wat het doet.

## General

- [ ] Controleer naam, omschrijving en zichtbaarheid van de repository.
- [ ] Voeg relevante topics toe, bijvoorbeeld `github-foundations`, `gh-900` en `learning`.
- [ ] Controleer de standaardbranch (`main`).
- [ ] Bekijk welke opties onder Features beschikbaar zijn: Issues, Projects, Discussions en Wiki.

## Collaborators en teams

- [ ] Lees in GitHub Docs wat Read, Triage, Write, Maintain en Admin betekenen.
- [ ] Leg vast welke minimale rol een reviewer nodig heeft en waarom.
- [ ] Nodig niemand uit met Admin-rechten alleen om een review te kunnen doen.

## Branches en pull requests

- [ ] Maak een branch protection rule of ruleset voor `main`.
- [ ] Oefen de gevolgen van 'require a pull request before merging'.
- [ ] Voeg, indien beschikbaar, de repository-check als vereiste statuscheck toe.
- [ ] Vergelijk merge commit, squash merge en rebase merge. Kies bewust één methode voor dit lab.

## Security

- [ ] Bekijk Security > Code security and analysis en noteer welke functies beschikbaar zijn voor dit type repository.
- [ ] Lees de security policy via het tabblad Security.
- [ ] Controleer waar Actions secrets zouden worden opgeslagen. Maak nooit een echt geheim alleen voor een oefening.

## Projectmanagement

- [ ] Maak een Project met de velden Status en Priority.
- [ ] Maak een milestone `GH-900 preparation`.
- [ ] Koppel minstens drie issues aan de milestone en het Project.

## Bewijs

Noteer na afronding links naar je ruleset, Project en voorbeeld-PR in [study/exam-objectives.md](../study/exam-objectives.md). Publiceer geen screenshots met e-mailadressen of gevoelige instellingen.
